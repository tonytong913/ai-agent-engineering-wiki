# Memory 与 Context Engineering

## 交流定位

Memory 和 Context Engineering 决定 Agent 是否能在长任务中保持连续性，同时不被历史噪声拖垮。技术交流重点是上下文预算、摘要、检索、长期记忆和污染控制。

## 核心概念

- **短期上下文**：当前会话消息和工具结果。
- **长期记忆**：跨会话保存的用户偏好、项目知识和历史决策。
- **检索记忆**：根据当前任务动态取回相关片段。
- **压缩**：用摘要或裁剪降低 token 占用。
- **Prompt cache**：保持稳定前缀以减少成本和延迟。

## 工程实现

- 将上下文分层：系统指令、用户输入、任务状态、工具结果、检索材料、记忆。
- 为不同层设置优先级，接近窗口上限时按优先级裁剪。
- 长期记忆写入需要触发条件和审查，避免把错误结论永久保存。
- 检索结果要带来源，方便解释和调试。
- 摘要不能替代所有原文，关键证据和工具输出需要保留可追溯路径。

## 项目表达

可以讲一个“上下文预算治理”的项目：通过 token 估算、优先级裁剪、摘要、检索和缓存稳定前缀，降低成本并提升长任务完成率。

# RAG 与检索增强

## 面试定位

RAG 是企业 Agent 的常见基础能力。面试重点不是“向量库怎么用”，而是文档处理、召回、rerank、上下文构造、引用、权限和质量评估。

## 核心概念

- **文档解析**：把 PDF、网页、代码、表格等转为可检索文本。
- **Chunking**：按语义、结构或 token 长度切分文档。
- **Embedding / BM25 / Hybrid**：分别覆盖语义召回、关键词召回和混合召回。
- **Rerank**：对召回结果重新排序，提高上下文质量。
- **Grounding**：答案需要基于证据，并能给出引用。

## 工程实现

- 文档入库要保存来源、权限、版本、更新时间和结构信息。
- Query rewrite 可提升召回，但要防止偏离用户问题。
- 上下文拼接要控制长度、去重和证据排序。
- 权限过滤应在召回前或召回中执行，不能只在答案后处理。
- RAG eval 要同时看召回质量、答案忠实度和用户任务成功率。

## 常见面试题

- 如何设计 chunking 策略？
- hybrid search 和 rerank 分别解决什么问题？
- RAG 如何避免幻觉？
- 长上下文模型是否可以替代 RAG？

## 追问点

- 文档权限如何进入检索链路？
- 如何评估检索结果是否覆盖正确证据？
- 如果召回正确但答案错误，问题可能在哪里？

## 项目表达

可以讲一个“企业知识库 Agent”的项目：从文档接入、权限过滤、检索、rerank、上下文构造、引用生成到 eval 闭环。

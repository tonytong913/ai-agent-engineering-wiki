# Tool Calling / MCP / 工具生态

## 交流定位

工具调用是 Agent 从文本生成走向真实行动的边界。技术交流重点通常是 schema 设计、权限、安全、执行协议、失败恢复，以及 MCP 这类标准化工具生态的接入方式。

## 核心概念

- **Tool schema**：向模型描述工具名、用途、参数和约束。
- **参数校验**：模型输出必须经过结构化校验，不能直接执行。
- **权限系统**：区分只读、高风险、写入、网络、文件、命令等工具。
- **执行协议**：工具调用输入、执行状态、结果、错误和副作用需要标准化。
- **MCP**：把工具、资源、提示词通过标准协议暴露给 Agent。

## 工程实现

- 工具注册时保存 schema、执行函数、权限策略、并发能力和结果格式。
- 调用前做 schema 校验和权限判定，调用后做结果归一化。
- 对高风险工具增加人工确认、沙箱或 allow / ask / deny 策略。
- 工具很多时使用工具发现、分组、渐进加载或检索，避免 prompt 过长。
- MCP 接入要考虑 server 生命周期、transport、鉴权、超时和版本兼容。

## 常见技术交流问题

- Tool schema 应该如何设计？
- 如何避免模型误用工具？
- MCP 解决了什么问题？
- 工具执行失败后如何把错误反馈给模型？

## 追问点

- 工具调用有 side effect 时如何保证幂等？
- 多个工具并发执行时如何做权限和资源隔离？
- 工具返回大量内容时如何控制上下文污染？

## 项目表达

可以讲一个“工具平台化”的项目：统一注册工具、生成 schema、做权限治理、记录 trace，并支持 MCP 或内部工具协议扩展。

# Harness 工程

## 交流定位

Harness 工程关注“如何让 Agent 可测试、可复现、可评估、可迭代”。它连接任务集、运行环境、工具、日志、评分和回归，是把 Agent 从 demo 推向工程系统的关键。

## 核心概念

- **Harness**：围绕 Agent 构建的测试和执行外壳，负责输入、环境、工具、评估和记录。
- **任务集**：定义输入、约束、期望行为和评分方式。
- **轨迹记录**：保存模型消息、工具调用、环境状态、输出和评价结果。
- **可复现性**：固定数据、模型版本、提示词、工具版本和随机性。
- **离线与线上**：离线 harness 做评测和回归，线上 runtime 处理真实用户和安全边界。

## 工程实现

- 任务定义应包含输入、允许工具、环境准备、成功标准和超时限制。
- 每次运行生成 trace，记录 prompt、response、tool call、tool result、score。
- 支持 replay，用历史 trace 复盘失败原因。
- 用 golden set 做回归，避免提示词或模型升级引入隐性退化。
- 将评分分为规则评分、人工评分和 LLM-as-judge。

## 常见技术交流问题

- Harness 和 runtime 的边界是什么？
- 如何设计一个可复现的 Agent eval harness？
- 如何记录和回放一次 Agent 任务？
- 如何把离线评测结果用于线上迭代？

## 追问点

- LLM-as-judge 的偏差如何控制？
- 如果线上失败样本无法复现，你怎么排查？
- 如何保证工具版本变化不会污染 eval 结论？

## 项目表达

可以讲一个“为 Agent 建立评测 harness”的经历：从人工试跑变成任务集、trace、自动评分、回归看板，并用失败样本推动 prompt、工具和检索链路迭代。

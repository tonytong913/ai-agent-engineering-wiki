# Agent Loop 工程

## 交流定位

Agent Loop 是 AI Agent 工程能力的核心。技术交流方通常想确认你是否能把“模型会调用工具”落成稳定的 runtime：状态、工具、错误、预算、终止和可观测性都要被系统化处理。

## 核心概念

- **Loop 阶段**：输入收集、上下文组装、模型调用、工具解析、工具执行、结果回灌、终止判断。
- **终止条件**：模型给最终答案、达到最大轮数、预算耗尽、工具失败不可恢复、用户中断。
- **状态管理**：保存消息历史、工具结果、任务状态、预算、trace 和错误信息。
- **恢复机制**：工具失败、模型格式错误、超时、中断后需要有明确恢复策略。
- **Streaming Loop**：模型边生成边触发工具执行，提升延迟但增加状态复杂度。

## 工程实现

- 用显式状态机描述每轮 loop，而不是把所有逻辑塞进一个递归调用。
- 工具调用要经过 schema 校验、权限检查、执行调度、结果归一化。
- 每轮都更新 token、cost、latency 和 tool span，方便后续排查。
- 设置最大轮数和预算硬限制，避免无限循环。
- 对 side effect 工具使用幂等 key 或人工确认。

## 常见技术交流问题

- 一个生产级 Agent Loop 包含哪些阶段？
- Agent 如何判断任务已经完成？
- 如何防止 Agent 无限调用工具？
- 工具执行失败后，系统应该怎样恢复？

## 追问点

- Streaming tool execution 会带来哪些一致性问题？
- 多个工具并发执行时如何处理结果顺序？
- 用户中途取消任务时，已经触发的工具怎么办？

## 项目表达

可以讲一个“从简单链式调用演进到状态机 runtime”的项目：最初只支持单轮工具调用，后来加入多轮 loop、终止条件、trace、预算和错误恢复。

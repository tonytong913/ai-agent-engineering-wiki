# Agent 系统设计

## 面试定位

系统设计题考察你能否把 Agent 能力拆成稳定的工程模块。回答时要覆盖需求、架构、数据流、工具、权限、eval、可观测性、扩展性和故障处理。

## 核心概念

- **Runtime**：执行 Agent Loop，管理状态、工具和模型调用。
- **Tool layer**：注册、发现、权限、执行和结果归一化。
- **Memory / RAG layer**：提供上下文和知识。
- **Eval layer**：离线评测、线上监控、回归门禁。
- **Control plane**：模型配置、提示词版本、权限策略、工具版本。

## 工程实现

- 从用户场景和成功标准开始，不要直接画模型调用链。
- 画出请求链路：入口、鉴权、上下文、模型、工具、结果、trace。
- 明确同步和异步任务边界。
- 明确安全边界：哪些工具需要确认，哪些资源不能访问。
- 给出 eval 和 observability 方案，说明如何持续迭代。

## 常见面试题

- 设计一个代码 Agent 平台。
- 设计一个企业知识库 Agent。
- 设计一个 Agent 评测平台。
- 设计一个 MCP 工具管理平台。
- 设计一个支持多模型路由的 Agent runtime。

## 追问点

- 如何支持多租户和权限隔离？
- 如何控制成本和延迟？
- 如何灰度发布新的 prompt 或模型？
- 如何处理工具服务不可用？

## 项目表达

可以用“需求 -> 模块 -> 数据流 -> 失败处理 -> 指标”的顺序讲系统设计，避免只堆概念。

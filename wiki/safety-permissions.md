# Safety / Permissions / Sandbox

## 交流定位

安全与权限是 Agent 工程区别于普通 LLM 应用的重要部分。只要 Agent 能调用工具、读写文件、访问网络或执行命令，就必须有权限、沙箱、审计和注入防护。

## 核心概念

- **权限策略**：allow、ask、deny。
- **资源隔离**：文件、网络、进程、浏览器、数据库、密钥。
- **Prompt injection**：外部内容试图覆盖系统指令或诱导工具滥用。
- **Tool injection**：工具结果中夹带恶意指令。
- **Data exfiltration**：通过工具调用泄露敏感数据。

## 工程实现

- 工具执行前做权限检查，执行后记录审计日志。
- 高风险工具默认 ask 或 deny，不能仅凭模型判断是否安全。
- 对外部文档和网页内容做不可信标记，避免其覆盖系统指令。
- 沙箱限制文件路径、网络域名、进程能力和环境变量。
- 敏感信息进入上下文前要脱敏或做最小化暴露。

## 常见技术交流问题

- 如何设计 Agent 工具权限系统？
- 如何防御 prompt injection？
- 沙箱需要隔离哪些资源？
- 如何防止工具调用泄露敏感数据？

## 追问点

- 只读工具是否一定安全？
- 用户授权一次后是否可以长期复用？
- 如何审计一次危险工具调用？

## 项目表达

可以讲一个“高风险工具治理”的项目：对 shell、数据库写入或外部 API 调用增加分类、权限确认、沙箱执行和审计记录。

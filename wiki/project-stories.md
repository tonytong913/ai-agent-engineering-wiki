# 项目故事

## 交流定位

项目故事用于把技术能力落到“我做过什么、解决了什么问题、怎么取舍、结果如何”。AI Agent 工程技术交流中，项目故事往往比概念答案更能证明工程能力。

## 核心概念

- **STAR**：Situation、Task、Action、Result。
- **工程取舍**：为什么这样做，放弃了什么。
- **指标结果**：成功率、延迟、成本、人工节省、回归率、用户反馈。
- **事故复盘**：技术交流方会通过失败经历判断真实深度。
- **多版本表达**：30 秒版、2 分钟版、深挖版。

## 工程实现

- 每个项目绑定至少两个专题，例如 Agent Loop + Eval，或 Tool Calling + Safety。
- 每个项目准备核心架构图、关键数据流和一次失败案例。
- 讲指标时区分离线指标和线上指标。
- 讲职责时明确自己负责的模块、决策和结果。

## 常见技术交流问题

- 介绍一个你做过的 AI Agent 项目。
- 这个项目最难的问题是什么？
- 你如何证明这个 Agent 变好了？
- 如果重新做，你会怎么改？

## 追问点

- 这个方案为什么不用更简单的链式调用？
- 你怎么定位失败样本？
- 你的设计里最大的风险是什么？

## 项目表达

推荐结构：

1. 一句话定位项目。
2. 说明业务或工程问题。
3. 说明自己的职责。
4. 讲核心架构和关键取舍。
5. 给出指标和结果。
6. 主动讲一个失败和改进。
